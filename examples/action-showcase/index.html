Why we built it

Demos should not drift every time the product changes.

Live walkthroughs are hard to repeat. Recorded videos go stale the moment the UI moves. Automation scripts are rarely presenter-friendly. Here is where most demos die: three sprints later a button gets renamed, and nobody finds out until a prospect is watching.

So ScreenReel drives the real product instead of a recording of it — and because it drives the real product, it can tell when the product changed. One readable flow gets presented, personalized, branched, and rendered; flow doctor repairs the steps that broke, and CI fails the pull request that broke them.

What makes it different

Six things most demo tools can't do.

Each one is a live chapter you can play — nothing on those pages is mocked.

01 · Author

Perform it once

You don't write a demo. Use your app inside Studio's preview and the recorder writes the flow: keystroke bursts coalesce into one type at your measured speed, a click that navigates becomes goto, and password fields are never recorded.

See it recorded →

02 · Maintain

It refuses to rot

Three sprints later a button gets renamed. flow doctor re-matches it by fingerprint and rewrites only the keys that changed — and the validate-flows CI action fails the pull request that broke it, before a prospect ever sees it.

$ screenreel flow doctor --fix
repair  .flow-row
     →  [data-flow-step="1"]
confidence 100 — 1 fix applied
re-run: ok: true
See it repair itself →

03 · Produce

Give it a voice

You already wrote the script — it's the talking points on every scene. assemble --voice speaks them over the captured video: silence-padded, sync-safe, and rendered into the MP4. The default provider is macOS say, so there's no API key.

Played by your browser's speech engine — a stand-in for the say and ffmpeg pipeline that renders the real MP4.

See it narrated →

04 · Personalize

Say their name

Declare {{company}} once and every link carries its own value: ?srv_company=Northstar personalizes the whole run, across every page it visits. Selectors and navigation URLs are never interpolated, so a link can't steer targeting.

See it personalized →

05 · Distribute

Send it out

A ?demo=play link auto-plays with viewer chrome — progress, play/pause, exit. Every run reports its own funnel from view_start to flow_complete or drop_off, and nothing leaves the page unless you point it at a collector.

See it shared →

06 · Engage

Let them drive

A choice action shows up to four cards and jumps playback to the scene the viewer picked. Every target is graph-validated, so a branch can never dead-end — and capture auto-picks the default, so the rendered video stays linear.

See it branch →

How it works

A small contract, not another platform.

1

Record the flow

Press Record in Studio and use your product. The JSON is the artifact, not the input — readable, diffable, and yours.

2

Present and personalize

Mount Projector in the app. Share ?demo=play links that auto-play and greet each prospect by name.

3

Keep it honest

Run flow doctor in CI to catch and repair what a product change broke, then render the same flow as video.

Install from GitHub

Start with the same flow in your app.

npm install --save-dev "git+https://github.com/Alafazam/screenreels.git"
