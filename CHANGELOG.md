# Changelog

## Unreleased

- Added per-action narration: an action can carry its own `narration`, spoken as that action runs so the words land on the highlight, click, or scroll they describe instead of arriving as one paragraph when the scene opens. A scene's transcript is now its own line (`scene.narration ?? scene.talkingPoints`) plus one line per narrated action, and `ScreenReelCore` splits that contract into `sceneNarration`/`actionNarration`/`narrationScript` with `lib/voice.mjs narrationText` still pinned against the composed transcript by `test/narrator.test.mjs`. Only the timing differs between the two speakers: live, the projector speaks the scene line as the scene opens and hands each action line to the executor through a new `narrateAction` context callback (each line replaces whatever is still speaking — a queue would drift behind the picture); captured, there is no per-action audio timeline, so the whole transcript plays over the scene's clip. `narration` joined the interpolation allowlist, so a `?srv_company=…` link is heard saying the prospect's name in action lines too. Studio speaks action lines during scene preview and badges narrated actions in the timeline.
- Reworked the Studio scene editor: the seven-field form above the preview became a Settings modal, giving the preview the vertical space it was competing for. Route is no longer a bare text box — it gets a picker populated from every route the saved flows use, the page Studio was opened from, links found in the preview itself, and an optional `pages` mount option, plus a live line showing the URL the route actually resolves to and, on Apply, the same `normalizeRoute` validation the flow is saved with (a cross-origin URL now says which origin it landed on instead of "invalid"). Narration gets its own field with a Preview button that speaks through the engine a viewer hears. Also: an invalid JSON field in the action editor now toasts and aborts instead of silently skipping itself and half-writing the action, Esc closes the topmost modal, Cmd/Ctrl+S saves from the editor, modals focus their first field, action rows drag to reorder like scene rows already did (including rows the recorder appends), icon-only buttons carry tooltips, an unsaved Save button is accented, and the empty timeline explains recording instead of saying "Add the first action to this scene."

- Added live narration: the tour now speaks each scene's script aloud in the browser while it plays, from the same `scene.narration ?? scene.talkingPoints` that Capture's voiceover renders into the MP4. This is the live twin of `assemble --voice`, not a replacement — there is no ffmpeg in a browser and no `speechSynthesis` in Node, so both exist and `test/narrator.test.mjs` pins the two script-selection functions against each other so they can never speak different words for the same scene. On by default via a new `narration` mount option (`true` | `false` | `{ rate, voiceName, lang }`), with a speaker button in both the presenter pill and the share-mode viewer chrome; the mute persists per project and survives the flow's own hard navigations. Variables are interpolated first, so a `?srv_company=…` link is *heard* saying the prospect's name. When a scene's actions finish while narration is still talking, playback waits for the sentence to end rather than cutting it — capped at 6s, overridable per scene with `narrationCapMs` — which is the live answer to the overrun that `voice.overflow` solves by freezing a frame. Autoplay-blocked audio (share links auto-play with no user gesture) pulses the speaker button and toasts once, and tapping it both supplies the gesture and speaks the current scene; browsers with no installed voices hide the button rather than offering silence. Capture injects the action runtime and cursor but not Projector, so live narration cannot leak into a recording or double up with `--voice`.
- Gave all six shipped features a card on the landing page instead of three. Voiceover, flow variables, and share + analytics were previously a single closing sentence, which read as an afterthought next to the three that had cards. The `#features` grid is now the same six chapters the showcase tells, in the same order, each linking to its chapter. The voiceover card carries a working "Hear a narrated line" button so a visitor can hear what narrated talking points sound like — it uses the browser's `speechSynthesis` and says so on the card, because the real pipeline is macOS `say` through ffmpeg into the captured MP4 and cannot run in a browser. Same stand-in the showcase's voice chapter uses.
- Retold the landing page around the differentiator instead of the output formats. The hero now leads with "Record it once. It repairs itself.", a new `#features` section gives the three headline capabilities — record-by-doing, `flow doctor` self-repair, and viewer branching — one card each linking into its live showcase chapter, and the `Projector`/`Studio`/`Capture` grid was reframed from a competing "three tools" pitch into the surfaces that deliver those features. The three `[data-flow-step]` hero rows were rewritten so the guided tour's opening scene narrates the new story while keeping every selector the tour targets, and the one footer/OG/JSON-LD tagline now agrees across all three. The exact-H1 assertion in `scripts/browser-smoke.mjs` moved with it.
- Fixed the showcase journey being undiscoverable: the seven chapter pages carried `noindex` and no Open Graph tags, so the strongest copy on the site could not be found or shared. They are now `index,follow` with canonical, OG, and Twitter card metadata derived from each page's existing title and description, and `sitemap.xml` lists all seven alongside the homepage.
- Fixed `resolveChrome()` finding no browser on x64 Linux: it globbed only `chromium-*/chrome-linux/chrome`, but Playwright's layout is arch-dependent and x64 unpacks Chrome for Testing into `chrome-linux64/`. Every GitHub-hosted runner is x64, so CI downloaded Chromium and then failed to find it on the workflow's first-ever run.

## 0.3.0

- Added task-oriented documentation in `docs/`: one how-to guide per feature (recording, doctor + CI, voiceover, variables, sharing + analytics, branching, pacing + cursor), each with a quickest path, a reference table, troubleshooting, and an under-the-hood note. The README now points at them instead of duplicating detail, every showcase chapter links to its guide, and the landing page links the index.
- Fixed recorded actions carrying no `fingerprint`, which silently made recorded flows — the primary authoring path — ineligible for `flow doctor`'s automatic repair. Fingerprint capture now lives in one place (`ScreenReelCore.fingerprintFor`) used by the Studio picker, the recorder, and the doctor's scoring.
- Added the showcase journey (`showcase.html` + six chapter pages, linked from the landing nav and deployed with the Pages site): the demo-creator suite told as a story, where the guided tour drives itself across all seven pages — recording, doctor repair, voiceover, live `{{company}}` personalization, share mode, and a final viewer choice — while a sessionStorage-backed analytics feed counts the tour's own events across every hop. Flows live in `showcase.demo.json`, so `flow validate`/`flow doctor` work against the showcase too.
- Fixed share links carrying `srv_` variables breaking route matching: `normalizeRoute` now strips `srv_*` like `demo`/`screenreelPreview`, so a personalized link no longer forces a reload before playback.
- Added viewer choice cards: a new `choice` action (26th in the catalog) shows 1–4 clickable cards that jump playback to a named scene via a new additive `jumpTo` result channel; `timeoutMs` auto-continues to a required `defaultScene`; pause/disable removes the overlay and continues linearly. Targets are graph-validated (`ScreenReelCore.validateFlowGraph`, wired into Studio save and `flow validate`) — unknown or disabled targets are errors, since a disabled target would be a silent runtime no-op. Capture auto-picks the default (or first) option so recorded video stays linear. Each choice emits `screenreel:choice` plus a `choice` analytics event.
- Fixed `createCopy` breaking choice branches: scene ids are regenerated on duplicate, and choice option/defaultScene references now remap to the new ids (previously they silently pointed at the original flow's scenes — caught by the new graph validation in the browser smoke).
- Added share mode: `?demo=play` auto-plays the active flow with viewer chrome only (progress, play/pause, exit) and survives the flow's own cross-page navigations; exit restores presenter mode. Combines with `srv_` variables for personalized share links.
- Added funnel analytics: playback emits `view_start` (once per session), `scene_enter`, `scene_complete`, `flow_complete`, and `drop_off`, each enriched with session id, scene position, and percent complete. Delivered as `screenreel:analytics` CustomEvents, an `analytics.onEvent` mount callback, and an optional `analytics.beaconUrl` (sendBeacon with fetch-keepalive fallback). Nothing leaves the page unless a beacon URL is configured; payloads carry manifest identifiers only — no URLs, page content, or PII.
- Added flow variables: declare `variables` on a flow and use `{{name}}` in action text/notes/values and scene titles/talking points. Values resolve URL (`?srv_name=…`, session-persisted across navigation) > mount option > flow defaults, so one share link personalizes a whole run. Interpolation lives inside `runAction` behind an explicit field allowlist — selectors, function names, and `goto` URLs are never interpolated (URL-supplied values must not steer targeting; a goto interpolation would be an open redirect). Unknown names stay literal with a one-time warning, so existing flows are byte-identical. Studio gains a Variables editor; Capture reads flow defaults with `config.variables` overrides.
- Added voiceover to Capture: `screenreel assemble --voice` (or `voice.enabled` in config) narrates each scene from `scene.narration ?? scene.talkingPoints` through a pluggable local-first TTS provider — macOS `say` by default, any CLI via a `command` template, or a custom `synthesize` object. Every concat part carries a uniform AAC 48kHz stereo track (silence on cards and unnarrated clips) so the stitch cannot desync, verified by a per-part stream assertion. Narration longer than its clip freeze-extends the last frame (`overflow: 'extend'`) or truncates. First real use of the previously unused `@ffprobe-installer/ffprobe` dependency; ffmpeg/ffprobe resolution is now shared in `lib/media.mjs`.
- Added `screenreel flow doctor [--fix]`: re-validates a flow against the live DOM and repairs it — ambiguous selectors get a unique re-derived selector or `index: 0`; dead selectors are re-matched by the action's `fingerprint` (now stamped by Studio's target picker) and rewritten only above a confidence threshold; everything else is reported with ranked candidates. Repairs rewrite only the changed keys, preserving the rest of the file byte-for-byte. "Has no matches" after a state-mutating action downgrades to a warning (dry-run false positive).
- Added CI: `.github/workflows/ci.yml` runs unit tests + a committed-dist drift check, then browser-backed validation of the example flows and the full smoke suite on every PR — the first CI this repo has had. `.github/actions/validate-flows` is a composite action consumer repos can use to get inline PR annotations when a product change breaks their demo.
- Fixed `resolveChrome()` crashing on Node 20: `fs.globSync` is Node 22+, but `engines` allows `>=20`; the glob is now guarded.
- Added record-by-doing to Studio: a Record button in the scene editor turns trusted interactions inside the preview into flow actions live — keystroke bursts coalesce into one `type` with measured typing speed, checkbox/select/range changes map to `toggle`/`set`/`lever`, scroll bursts become one relative `scroll`, idle pauses become `afterMs` on the previous action, and a click that causes a navigation is replaced by `goto`. Recording appends rows incrementally (no re-render, so preview state survives), stops cleanly on any destructive editor change via the picker-cancel funnel, re-attaches across same-origin navigations, never records password fields, and ignores synthetic (non-`isTrusted`) events.

- Fixed the deployed live demo doing nothing on click. `build:pages` keyed cache-busting queries on the release version, so `app.js?v=0.2.1` kept its URL across a content change and the CDN went on serving the previous file; the stale copy's `const toast` collided with the new `fixtures.js` global of the same name, and the resulting SyntaxError stopped Projector from mounting. Cache keys are now content hashes, the two page scripts are wrapped in IIFEs so they cannot share global bindings, and the browser smoke test exercises `_site/` in addition to `examples/`.

- Added a shared agent cursor (`packages/core/cursor.js`) used by both Projector and Capture: it travels to each interaction target, emits position rings on arrival, dips with a ring burst on click and pointer taps, drifts while the page scrolls, and honours `prefers-reduced-motion`. It is created lazily on first use, so an idle page shows no pointer, and emphasis actions (highlight, glow, spotlight) deliberately do not move it. Projector now supplies `moveCursor` to the executor, so the existing cursor call sites are no longer no-ops in the browser. Configure with the `cursor` mount option (`'dot'`, `'arrow'`, or `false`).
- Added a `snippet` action that shows the code behind a step in a panel beside the target, docking to a corner when the target leaves no room. `keep` holds it on screen while later actions run.
- Added an intro beat: the control pill announces itself and the active flow before the first action runs.
- Added a runtime `timeScale` mount option and `ScreenReelCore.setTimeScale`, replacing per-example manifest rewriting. It scales the runtime's internal constants (countdown steps, flash pulses, reveal fades) that manifest rewriting could not reach, and presenter notes now ride the same scale.
- Added cursor travel and press feedback to `set` and `toggle`, which previously changed controls with no visible pointer.
- Fixed `flow.defaults.settleMs` being ignored during Projector playback; only `scene.settleMs` was read, so live and captured pacing diverged.
- Fixed scroll settling stalling in throttled or non-compositing tabs, where `requestAnimationFrame` can drop to about one frame per second; the settle check now races rAF against a timer.
- Re-cut the example guided tour to 6 scenes (~30s) and moved the showcase flow's drag, pointer, container-scroll, `waitFor`, and `call` fixtures to `destination.html`. Removed the "Explain each step as it plays" toggle and its floating panel.
- Fixed the example tour jumping to the top of the page after the form scene: scenes used `./#form` and `./` routes, so each hash change scrolled the document. Same-page scenes now share one route and rely on their own `scrollIntoView`.
